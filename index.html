Choose where rendering happens

Streaming SSR
Stream ready HTML while slower data loads. Hydrate completed regions without waiting for the full response.
Service-worker rendering
Cache the compiled UI, then stream rendered HTML fragments as data arrives. Your app owns the caching policy and first-load bootstrap.
WebAssembly (WASM)
Use the renderer or compiler in the browser. Choose handler-only, parser-only, or combined bundles.
Static site generation
WebUI Press builds Markdown and Web Components into static HTML. Publish to a CDN or static host.

Compile before requests arrive

Template structure is known before a request arrives. WebUI compiles it ahead of time, leaving your server to supply data and render HTML.

Start with HTML and CSS
Bindings, conditions, and loops render on the server. A component does not need a JavaScript class just to display data.
Add behavior, not a second page
Interactive Web Components connect to the rendered DOM. Observable state updates the bindings that depend on it.
Know what changes
Existing JSX and React libraries are not drop-in WebUI components. Initial state comes from your backend; styling follows the web platform.

Keep your backend

Load the compiled template once, then render with request data. Choose a supported binding or use the C interface from another language. A JavaScript SSR engine is not required.
