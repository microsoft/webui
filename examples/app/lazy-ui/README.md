# Lazy popover and dialog

A runnable example of inline `<if lazy>` bodies inside a native `popover` and
`<dialog>`. Each overlay is a component; its lazy body stays inline rather
than becoming another component or a route.

| Component | Owns |
| --- | --- |
| `lazy-workspace` | Reading list, shared slow-data control, cache control, and applied view preferences |
| `lazy-popover` | Native `popovertarget` controls, CSS anchor positioning, and the activity body (`lazy="idle"`) |
| `lazy-dialog` | Native `showModal()` / `close()`, draft preferences, and the settings body (`lazy="demand"`) |
| `layout-preview` | A miniature reading list in the draft layout; only the settings body uses it |

The workspace passes boolean attributes to its children, and the dialog emits
`preferences-applied`. Each overlay owns its request cancellation and local
state. `src/state-api.ts` is the only data helper: a plain `fetch()` of the
overlay's state from the sample API.

```bash
# From the repository root
pnpm install
cargo xtask dev lazy-ui
```

Open `http://127.0.0.1:3011`. `webui serve` renders the page and serves the
build's template packs from `_webui/packs/`. The small Node API on port `3021`
returns only state, at `/api/activity` and `/api/settings`.

## When each body loads

- **Recent activity** uses `lazy="idle"`. Once the page has loaded and the
  browser is idle, the framework fetches the activity pack at low priority. It
  renders nothing and requests no state.
- **View settings** uses `lazy="demand"`, so nothing fetches its pack on its
  own. The trigger prefetches it, and only the trigger:

  ```html
  <button @click="{onTrigger()}"
    @pointerenter="{$prefetch('settingsReady')}"
    @focus="{$prefetch('settingsReady')}">View settings</button>
  ```

  `$prefetch('settingsReady')` covers the regions whose condition reads
  `settingsReady`. Before the window `load` event it fetches at low priority,
  afterwards at high priority.
- Neither prefetch runs while the browser prerenders the page, and the idle
  prefetch is skipped when the user has turned on data saving.
- Clicking fetches fresh state and sets the overlay's condition. The framework
  renders the body from the prefetched pack, or fetches the pack first at high
  priority. The component awaits `this.$rendered()` only so the overlay never
  opens before its body exists.
- Enable **Simulate slow data** to observe loading feedback and cancellation.
- While loading, press Escape or click **Cancel activity load** / **Cancel settings
  load**. Loading and retry feedback stay beside the trigger, outside the overlay.
- Escape or Close removes the body and clears its request state. The popover
  also supports native light-dismiss. At the next idle period the framework
  releases the closed body's template; reopening reuses it if it is still in
  memory, or reloads the pack from the HTTP cache.
- Preferences affect only the current page. The content is illustrative sample data.
- `/?open=popover` and `/?open=dialog` render an initially active body on the
  server, with its template inline and no pack request.
- **Clear template cache** releases unused cached definitions without removing
  the live workspace; opening again reacquires what is needed.

Only the triggers, empty native containers, and their external loading/error
feedback are eager. Every element inside the popover and dialog, including
headings, close buttons, and form controls, belongs to its lazy body.

## Component scripts

Packs carry templates and styles, not JavaScript. `layout-preview` has its own
script: it measures how many rows fit at the draft spacing and updates the
caption when the spacing changes. Only the settings body uses it, so the build
lists it in a generated module, `.webui/lazy.webui.js`:

```js
// Generated by WebUI. Do not edit.
import { defineLazyScripts } from '@microsoft/webui-framework/lazy.js';

defineLazyScripts({
  "lazy-dialog::lazy:@0": {
    "layout-preview": () => import("../src/layout-preview/layout-preview.ts"),
  },
});
```

`src/index.ts` imports this module instead of `@microsoft/webui-framework/lazy.js`
and never imports `layout-preview` itself. esbuild compiles the dynamic import
into a separate `layout-preview-<hash>.js` chunk. Pointing at or focusing
**View settings** starts the pack and that chunk in parallel, and the body
mounts only after both have arrived, so the preview is already defined when it
is inserted. For `/?open=dialog`, the chunk loads while the page hydrates.

After building the workspace packages, `pnpm run build` runs `webui build`
twice around the client bundle, then type-checks:

1. `build:modules` builds without the projection manifest and writes
   `.webui/lazy.webui.js` (`--modules-out ./.webui`).
2. `build:client` bundles `src/index.ts` with `../../build-client.mjs`, which
   also writes `dist/webui-projection.json`.
3. `build:protocol` builds `dist/` with that manifest. The generated module
   does not depend on the projection, so it stays the same.

`start:server` passes `--modules-out ./.webui` as well, so `webui serve --watch`
keeps the module current after each rebuild, and the esbuild watcher picks up
any change. `src/index.ts` cannot be bundled or type-checked until the module
exists.

## Failures

When a body's pack or a component script cannot load, `$rendered()` rejects and
the owner receives a cancelable `lazyerror` event. Without a listener that
cancels it, the error goes to `reportError()`.

- `lazy-dialog` handles `lazyerror` (`onLazyError()`): it cancels the event,
  closes the dialog, resets `settingsReady`, and shows **Try again** beside the
  trigger. This also covers a dialog rendered open by the server, whose preview
  script loads during hydration rather than from `open()`.
- `lazy-popover` reports the rejection of `$rendered()` in `load()` and cancels
  `lazyerror`, so the failure is reported once.
- A failed prefetch is silent. **Try again** sets the condition again, which
  retries the request.

## Asset base

Stylesheet links, pack paths, and the stylesheets a pack names are relative to
the asset base, which maps to `dist/`. By default the asset base is the
document's base URL, so the same build works in the demo catalog's
subdirectory. A host that serves `dist/` from elsewhere, for example a CDN
whose path is known per request, sets the reserved state member:

```json
{ "$webui": { "assetBase": "https://cdn.example.com/b123/" } }
```

`webui build --asset-base <BASE>` sets a build-wide default instead. Packs on
another origin need CORS. `./index.js` in `src/index.html` is an authored URL,
so it and the bundler chunks it imports still load from the page's origin.
State requests resolve against the document's base URL. The tests serve
`dist/` from a second origin this way and check that the stylesheets and packs
come from there.

## Tests

```bash
pnpm --dir examples/app/lazy-ui build
pnpm --dir examples/app/lazy-ui test
```

The tests cover initial omission, the idle prefetch without rendering or state,
the scoped prefetch from **View settings** fetching only the settings pack,
loading the preview's chunk with the body and inserting it already upgraded,
warm packs with fresh state, native anchoring and dismissal, component
attributes and events, cancellation, pack and state failures with retry,
`lazyerror` handling without uncaught errors, SSR, cache collection and reopen,
the base path, low-priority speculative requests before the `load` event, an
asset base on a second origin, and narrow viewports.
